# Agent Buddy: security and privacy review pack (draft)

Status: draft for the security team. Every claim that a test enforces names the test. Anything not yet verified on a real
instance is marked **unverified**. Version 0.1.0, second hardening round (2026-10-30): a second independent audit
(`docs/review/security-audit-2.md`), the review pack (`docs/review-pack/`), and the enterprise build.

## 1. What it is

A Chrome/Edge extension for ServiceNow fulfillers (IT, customer service, HR cases, catalog) and their team leads. It reads
the ticket the person already has open, masks personal data, asks an AI model of the organisation's choice for a summary,
reply draft, resolution notes and similar, and lets the person insert the result into the open form. It has no server, no
account, no analytics.

## 2. Data flow

```
ServiceNow page (user already signed in)
   |  content script: GET-only reads with the user's own session (ACLs apply)
   v
Side panel (extension page)
   |  PII firewall: detect -> replace with [PLACEHOLDERS] -> seal -> (preview, user confirms)
   v
AI endpoint chosen by the person or the organisation   <- the ONLY other network destination
   |  response
   v
Side panel: placeholders replaced with the real values locally; shown as plain text; Insert fills one form field
```

Destinations: (1) the user's own ServiceNow instance, (2) the AI endpoint. Nothing else. No vendor server exists.

The side panel is where every action runs and every answer is shown. The one thing Agent Buddy draws inside a ServiceNow page is a
small bar of main actions (section 4, "The bar on the page"); it runs nothing itself: a click opens the side panel and the panel runs
the action behind the usual preview. The organisation can remove it with the policy key `disablePageBar`.

## 3. Permissions and justification

| Permission | Why | Enforced by |
|---|---|---|
| `storage` | Settings, snippets, key (per chosen mode), local audit log | manifest test |
| `sidePanel` | The panel is where actions run and answers are shown; also lets the click on the bar in the page open it | manifest test |

Localhost is for a local model. Not requested: `tabs`, `history`, `cookies`, `webRequest`, `debugger`, `downloads`, `clipboardRead`, `nativeMessaging`, static
host permissions, static content scripts, `web_accessible_resources`, `externally_connectable`, keyboard commands.
(`tests/manifest.test.js` fails if any of these appear.)

Extension-page CSP: `default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' data:; font-src 'self'; connect-src
https: http://localhost:* http://127.0.0.1:*; base-uri 'none'; form-action 'none'; frame-ancestors 'none'`. No `unsafe-eval`, no

address; the gate there is the per-host browser permission above.

The **enterprise build** (`npm run build:enterprise -- enterprise/<name>.json`, `docs/deployment.md`) compiles one organisation's
hosts in: `host_permissions` lists exactly its instances and AI host, with no optional hosts, so nothing else can be requested;
`connect-src` is exactly the AI origin; the config's policy is compiled in as a floor that the managed policy can only tighten. The
config is validated strictly (https only, http only for localhost/127.0.0.1, canonical addresses, no wildcards, no keys) and the
build refuses to write into `dist/`. Enforced by `tests/policy-enterprise.test.js` and `tests/manifest.test.js`.

## 5. Known limits (stated plainly)

1. **Names with no cue can be missed.** Emails, phone numbers, card and ID numbers and secrets are found by pattern. People on the
   record are masked exactly. A name written in the text is masked when the words around it mark it as a name ("Hi Tom,",
   "Regards, Anna Schmidt", "Dr. Priya Raman", "my manager is ...", "spoke with ...", "cc:", "per ...", @mentions). A name with
   nothing around it ("Carol Diaz joined") still passes in Standard mode, and a name made only of IT vocabulary, a weekday or a month
   ("June", "Teams") is left alone on purpose. The detector is a guess, measured on our own corpus rather than customer data.
   Mitigations: the preview, where the person can mask anything still visible ("Hide something else"); Strict mode, which also masks
   capitalised full names with no cue; a local model.
2. **The key is on disk unless it is memory-only.** "This browser" (the default) keeps it in Agent Buddy's own database in the
   browser profile: ServiceNow pages and Agent Buddy's content scripts cannot read it, but anyone or any malware that can read the
   profile on disk can. "Encrypted" is only as strong as the passphrase. A key supplied by policy (`providedApiKey`) sits in the
   managed-policy store (registry or policy file), readable by local processes. Recommended for an approved rollout: policy
   `keyStorage = session`, or a gateway that issues short-lived or per-person keys. Settings shows what is saved as the first and last
   four characters and the length; the whole key is shown only when the person presses "Show saved key" (hidden again after 20
   seconds, never offered for a key the organisation supplies, never in the side panel). A key being typed can be shown with "Show".
   A pasted key is cleaned (quotes, "Bearer ", whitespace) before it is saved.
3. **The page can see the bridge events.** A script on the ServiceNow page can observe or forge the bridge's answers; they
   are treated as data to check, never as authority. A hostile page script could already read the same form.
4. **Workspace forms** use shadow DOM, so "Insert" may fall back to Copy there. **Unverified** on a real Workspace.
5. **The AI provider sees the masked text.** The organisation's contract with that provider governs retention.
6. **`connect-src https:` in the normal build** (section 3). The enterprise build narrows it to the AI origin and grants host access
   to the configured hosts only.
7. **Blocked tables are enforced at the read boundary from two copies of the policy.** The content script asks
   `chrome.storage.managed` every 30 seconds, and the side panel (which can read it) sends its normalised policy with every read; the
   two are merged, so the panel can only make a read stricter (`tests/policy-panel-merge.test.js`). Whether a content script can read
   `chrome.storage.managed` itself is **unverified** (`docs/live-questions/policy.md` question 1); the panel's copy covers that case.
   A table reached through a dot-walked column is matched by the column's name, which for variables is the table's name
   (`sc_item_option`, `item_option_new`). Counts of the base table `task` do not tell classes apart.
8. **A person named only inside another ticket's prose is masked only when a cue names them.** People on the columns of the rows
   (caller, opener, assignee, contact...) are masked exactly. A colleague or customer mentioned in a close note is masked when the
   text introduces them ("spoke with Anna Schmidt", "cc: ...", "per Kevin") and passes when it does not. The preview is mandatory for
   these requests, so the person can see the text and mask what is left. Strict mode and a local model remain the stronger answers.
9. **HR detection is by table name.** `sn_hr_` plus the policy's `sensitiveTablePrefixes`. A record addressed by the base class
   `task` is resolved to its real class (one small read); a record addressed through another custom parent class is not
   re-resolved, so add the customer's HR prefix to `sensitiveTablePrefixes`. Legal, employee-relations or security-incident tables
   are ordinary unless a prefix or `blockedTables` names them.
10. **"Pinned endpoint" means the policy sets `aiProvider` or `aiBaseUrl`.** `aiProvider: openai` alone still allows the public
    OpenAI address; pin `aiBaseUrl` as well (docs/deployment.md) for HR.
11. **The daily token budget is counted on this computer** from the local usage log. A second browser profile has its own count, and
    one request can overshoot the number because the tokens are known only after the call. The budget is applied before every send
    (`executeRun`); if the usage log cannot be read the call goes ahead (the person's own caps still apply).
12. **The text to insert passes through an event the page can read.** When the person presses Insert, the panel sends the text (real
    names back in) to the content script, which hands it to the page-world bridge as a `CustomEvent` on the page's document. Any script
    on the ServiceNow page (a third-party widget, a session-replay tool, a script injected through a vulnerable widget) can listen for it
    and read the text, also when the insert then fails and the person uses Copy. The page has to receive the text to put it into the
    form, so this can be stated, not removed. It is the text the person is about to save into that form anyway, one field at a time.
13. **On a portal page the box is chosen by name, not by the ticket's own widget.** The bridge scores every visible text box by its
    name, ng-model, label and placeholder; it never writes a customer box into a work-notes box (or the reverse), refuses when two
    boxes tie and never presses a button. A page whose only "Comments" box belongs to another widget (an approval comment, a survey)
    would receive the reply. The panel says which box it used ("It went into the box labelled ...") so a wrong box is easy to see
    before Send is pressed. **Workspace insert is unverified** on a real Workspace.
14. **Internal notes can inform customer-visible drafts.** The reply, missing-information and email drafts are given the record's work
    notes as context; the prompt keeps them out of the draft and the send check flags 6 or more words copied from a work note, but a
    paraphrase of internal content passes. The agent reads every draft before it is inserted.
15. **The page can tell that the bar exists.** It is one `div` on the page's `<html>` element, with a `style` attribute and no id,
    class or name. The page cannot look inside, read its text or press it, but a page script can find the element, so the page can tell
    that something is there, and can cover it with its own element (which only hides it). Covering, restyling, moving or flashing the
    bar makes a click start nothing. A script that tricks a person into clicking the bar can at most start one of the bar's 3 or 4
    actions on the ticket that is open, which still stops at the preview (unless the person chose "never show") and sends only to the
    AI the person already chose.
16. **The bar reads the record while the panel is closed.** It looks at the page every 2 seconds to know which record is open: the
    classic form's own data from the page bridge, or the address on Workspaces and portals. An address that carries only a record
    number is looked up once (one GET, through the same blocked-table check as every read) and remembered. That is the one read Agent
    Buddy makes without the panel being open. While the bar is switched off it reads nothing.
17. **Closing `chrome.storage.local` to content scripts depends on the browser.** The service worker asks for it
    (`setAccessLevel`); where the browser does not support it for `local`, a compromised ServiceNow page process could read or change
    settings and the activity log (never the AI key, which is in the vault or in session storage). **Unverified** on Chrome 116+ and
    Edge (`docs/review/security-audit-2.md`). Use policy `keyStorage: session` for the strictest set-up.

## 6. Threat model summary

| Threat | Outcome |
|---|---|
| Malicious ticket text tries to steer the model | No tools, no actions, plain-text output; worst case is a misleading draft the person reads before using. |
| Model output tries to leak data through an image or link | Not rendered; shown as text. |
| Compromised page script | Can read what the page already has; cannot reach the AI key (extension pages only, kept where content scripts cannot open it) or write through the extension; cannot press the bar or start anything with a covered or restyled bar. |
| Stolen AI key | Limited by the provider-side spend cap and by sending only to its own host; mode and policy options above. |
| Malicious update | Distribution through the organisation's controlled channel (private/unlisted store listing or force-install with a self-hosted update URL); build is reproducible from source (`npm run repro`; verify with `node scripts/hashes.js <dir> --check SHA256SUMS`). |
| Over-collection | Field allowlists, HR free text off by default, tables and fields blockable by policy. |
