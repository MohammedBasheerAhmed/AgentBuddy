# Agent Buddy: STRIDE threat table

One row per threat. "Test" names the automated test that fails if the control is removed (`npm test` runs them all); a row without a
test says why. "Owner" is the role that keeps the residual risk acceptable. Diagram: `data-flow.svg`. Limits referred to as "limit N"
are in `docs/security.md` section 5.

Owner roles: **Maintainer** (whoever changes Agent Buddy's code), **Endpoint admin** (browser policy and device management), **ServiceNow
admin** (the instance, its ACLs and its page scripts), **Security team** (approval, network and the AI contract), **Agent** (the person
using it), **Team lead**.

| ID | Threat | Component | Control | Test | Residual risk | Owner |
|---|---|---|---|---|---|---|
| S1 | A web page or another extension sends requests to the service worker as if it were an Agent Buddy page | Service worker | Only this extension's own pages may ask for anything: the sender's id is this extension's and the sending frame's origin is exactly the origin of its own pages, from `runtime.getURL('')` (`chrome-extension://<id>` in Chrome and Edge; in Firefox `moz-extension://<a random id made at install>`, which is not the add-on id); an unknown id or origin refuses everything. A content script may send only the bar's two requests, from the top frame of a site the person turned on | `tests/senderCheck-content.test.js`, `tests/platform.test.js`, `tests/bar-background.test.js` | A compromised extension page would be a full compromise; there is no remote code that could do that. Firefox: not yet checked on a real instance | Maintainer |
| S2 | A page script forges the bridge's answers (record id, form values, "inserted") | Page bridge, content script | Answers are data to check, never authority; an insert names the record it was written for and is refused on any other (`wrong-record`) | `tests/insert-content-fill.test.js`, `tests/portal-bridge.test.js` | A hostile page can make an insert fail or lie about the form; it could already change the form itself (limit 3) | ServiceNow admin |
| S3 | A look-alike site (`acme.service-now.com.evil.test`) or a wildcard is taken for an instance | Policy, Settings | Instances are exact https hosts; a host with `*`, a user name or another scheme is refused; policy wildcards need two labels and never match the bare domain | `tests/policy.test.js`, `tests/policy-keys.test.js` | An administrator's own wildcard (`*.corp.example`) trusts every sub-domain of it | Endpoint admin |
| S4 | Traffic to the AI endpoint goes to an impostor | Provider layer | https only (http only to this computer); the policy can pin the address; the enterprise build's CSP allows only that origin | `tests/policy.test.js`, `tests/policy-enterprise.test.js` | Relies on the browser's TLS checks and the organisation's own proxy certificates | Security team |
| S5 | A page script presses the bar on the page | Bar on the page | Closed shadow root; only real clicks (`isTrusted`) count; the panel still shows the preview | `tests/bar-logic.test.js`, `tests/quick-launch.test.js` | A trick that makes the person click can start one action, which stops at the preview (limit 15) | Maintainer |
| T1 | Agent Buddy changes ServiceNow data | Content script | Only GET requests; Insert fills one allowed field of the record it was written for and never saves | `tests/readonly.test.js`, `tests/insert-fillable.test.js` | The person can save a wrong draft; ServiceNow's ACLs and audit trail apply to that save | Agent |
| T2 | Model output puts markup or a script into a form field | Insert | Plain text is escaped for HTML fields; the send check stops markup, secrets and unreplaced placeholders | `tests/insert-fillable.test.js`, `tests/insert-review.test.js`, `tests/render-safetext.test.js` | A paraphrase of internal notes in a customer reply passes (limit 14) | Agent |
| T3 | A person loosens the organisation's policy by editing their settings | Settings | The policy is applied on top of the person's settings every time they are read; floors can be raised, never lowered | `tests/policy.test.js`, `tests/policy-keys.test.js` | Someone with administrator rights on their own computer can remove the policy | Endpoint admin |
| T4 | A changed build or a poisoned dependency is installed | Build and update | Lockfile with integrity hashes, exact versions, SBOM, reproducible build with published hashes (`npm run repro`, and `-- --browser firefox` for the Firefox build), no remote code, strict CSP, distribution through the organisation's channel; Release and Beta Firefox install only packages Mozilla signed | `tests/manifest.test.js`, `tests/reviewpack.test.js` (SBOM current), `npm run repro` | Trust in React and esbuild at the pinned versions; the update channel must stay under the organisation's control; for Firefox, Mozilla signs each release and is a party in the release chain, as Google and Microsoft are for their stores | Security team |
| T5 | A typo in the managed policy silently drops a control | Policy | Chrome and Edge reject values that do not match the schema; `scripts/check-policy.js` lists every ignored or re-read key before rollout; an AI address that is not valid blocks AI calls; an enterprise build has the policy compiled in, so a typo cannot remove it; the Firefox samples carry the policy as one JSON text, so true and false stay true and false | `tests/policy-keys.test.js`, `tests/policy-enterprise.test.js`, `tests/selfhost-firefox.test.js` | In the normal build, a key the browser drops is "not set". Firefox checks no value against the schema: a value of the wrong type (a true written as 1) reaches Agent Buddy, which ignores it, and `about:policies` shows no error; `scripts/check-policy.js` does not read the Firefox files yet | Endpoint admin |
| T6 | The Firefox build is not what was reviewed for Chrome and Edge | Build | One source and one lockfile; the Firefox manifest is made from `manifest.json` with only the listed differences (background as an event page, `sidebar_action`, no `sidePanel`, the gecko id and Firefox 128 as the floor) and widens nothing; only `src/lib/platform.js` touches the browsers' panel APIs; the compile check covers both browsers | `tests/manifest-firefox.test.js`, `tests/manifest.test.js`, `tests/platform.test.js` | The Firefox bundles are compiled for another target, so their bytes differ from the Chrome build: hash each build on its own. Not yet checked on a real instance (`docs/live-questions/firefox.md`) | Maintainer |
| R1 | Nobody can tell who sent what to the AI | Audit log | Local log of every run, insert and copy: feature, table, salted record hash, provider and model, counts; no content; CSV export | `tests/audit.test.js`, `tests/insert-audit.test.js` | The log is on the person's computer and they can clear it; there is no central copy | Team lead |
| I1 | Personal data reaches the AI provider | PII firewall | Every request is masked and sealed; the provider layer refuses anything not sealed; preview of the exact text | `tests/seal.test.js`, `tests/pii-*.test.js`, `tests/pipeline.test.js` | A name written in prose and on no column of the record can pass (limits 1 and 8) | Maintainer |
| I2 | More of the record is read or sent than the action needs | Context reader | Field allowlists per action and record type; HR free text off unless policy allows it and pins the endpoint | `tests/context-*.test.js`, `tests/policy-hardening-policy.test.js` | HR detection is by table name (limit 9) | ServiceNow admin |
| I3 | Model output leaks data through an image or a link that loads | Answer display | Answers are plain text; no HTML, no images, no loading links | `tests/render-*.test.js` | A person may copy a link by hand | Agent |
| I4 | The AI key is stolen from the browser profile | Key store | Key modes (memory only, passphrase-encrypted); the policy can force memory only or supply the key | `tests/keystore.test.js`, `tests/policy.test.js` | Default mode keeps the key in browser storage (limit 2) | Endpoint admin |
| I5 | Page scripts read the text being inserted | Insert | Stated, not removable: the page must receive the text to fill the field; one field at a time | none: a design limit (limit 12) | A third-party widget on the page can read the inserted text | ServiceNow admin |
| I6 | Data goes to a destination other than the instance and the AI endpoint | Extension pages | No telemetry; only the provider layer and the content script's GET client call `fetch`; CSP; the enterprise build narrows connect-src to the AI origin and host access to the configured hosts | `tests/readonly.test.js`, `tests/manifest.test.js`, `tests/policy-enterprise.test.js` | The normal build's CSP allows any https address (limit 6); the browser permission per host is the gate there | Security team |
| I7 | Ticket content is kept on disk | Storage | Only settings, keys and counts are stored; every stored key is listed and can be cleared | `tests/insert-stored-data.test.js`, `tests/checks-store.test.js` | The browser's own memory and crash dumps | Maintainer |
| I8 | A table the organisation blocked is read | Content script | Blocked tables are refused where data is read and again before any AI run | `tests/policy-hardening-guard.test.js`, `tests/policy-panel-merge.test.js` | Whether a content script can read the managed policy is unverified; the panel's copy covers it (limit 7) | Endpoint admin |
| D1 | Runaway cost or abuse of the AI account | Provider layer | Per-person caps and the policy's daily token budget, checked before every send | `tests/policy-hardening-pipeline.test.js` | Counted per computer; one request can overshoot (limit 11) | Team lead |
| D2 | A hostile page floods the extension | Bar, bridge | Two bounded request types; a launch request expires after 30 seconds and names the exact record | `tests/quick-launch.test.js`, `tests/bar-background.test.js` | It can only disturb the person's own tab | Maintainer |
| D3 | A wrong policy stops Agent Buddy for everyone | Policy | Fails closed with a plain message; `scripts/check-policy.js` before rollout; the browser's policy page shows schema errors (`chrome://policy`, `edge://policy`; Firefox's `about:policies` shows only JSON it could not read) | `tests/policy-keys.test.js` | A misconfiguration stops the tool rather than loosening it, by design. In Firefox a policy change takes effect only after a restart | Endpoint admin |
| E1 | Instructions inside ticket text steer the model | PII firewall, prompts | Ticket text is wrapped as untrusted data; the model has no tools and can only return text | `tests/pii-firewall.test.js`, `tests/seal.test.js` | A misleading draft, which the person reads before using | Agent |
| E2 | The extension gets access to more sites than intended | Manifest, Settings | No static host access in the normal build; one host at a time; `*` or a wildcard is never requested; the enterprise build grants exactly the configured hosts and can request nothing else | `tests/manifest.test.js`, `tests/policy-keys.test.js`, `tests/policy-enterprise.test.js` | In the normal build without `allowedInstances` a person can still grant any single https host | Endpoint admin |
| E3 | Agent Buddy acts beyond the person's ServiceNow rights | Content script | The person's own session only; no admin endpoints; a refusal is shown as such, never worked around | `tests/readonly.test.js`, `tests/context-access.test.js` | None beyond the person's own rights | ServiceNow admin |
| E4 | Code in a ServiceNow page reaches the AI key or the provider layer | Content script | Content scripts never import the provider layer, the key store or the firewall; the key is only read by extension pages | `tests/readonly.test.js`, `tests/keystore.test.js` | None known | Maintainer |
