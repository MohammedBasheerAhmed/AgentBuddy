## The findings that mattered most

- Invisible characters (direction marks common in Arabic pasted from Outlook) hid an email or a card number from masking.
- People past the 30th on a record (approvers, task owners) were sent unmasked.
- "Local only" did not stop Test connection from contacting a cloud AI.
- The policy guard compared dot-walked column names with blocked table names, so `request.requested_for` passed with `sc_request` blocked.
- The check before sending was reused across tickets: a "first time" full check could show as the short one.
- Matching a note's author to the customer kept only a to z: an Arabic name was never the customer.
- The Workload widget crashed for teams over 12 people; the custom report editor crashed as it opened.
- A test filter or a scenario id that matched nothing reported success; one read-only guard test scanned nothing on Windows.

## Still yours to decide

1. **Push.** Nothing is pushed. When you push, CI runs the new jobs (Windows unit tests, e2e on the minified build, lint); if branch
   protection lists required checks, add them.
2. **One meaning of a ticket's state.** Five classifiers disagree, so the Insights card order, the AI Assist suggestions, My work and the
   checks can file the same state differently:
   - "Open": new (insights order) / working (stages, reports) / open (My work).
   - "Pending", "Awaiting Approval": new (stages) / waiting or on hold (the others).
   - "On Hold": working (stages) / on hold (the others).
   - "Closed", "Complete", "Cancelled": resolved (reports, My work) / closed (insights order, stages).
   - "Fulfilled", "Skipped": not classified (stages) / other (reports) / resolved or finished (the rest).
   - "Incomplete": closed (insights order) / open (My work) / not finished (checks).
   - "Review": resolve (stages) / working (the others). "Scheduled": new (reports) / working (the others).
     "Requested": open (My work) / new (the others).
   One shared classifier would end this, but every choice changes what someone sees: say which meaning each state should have.
3. **One reader of "Label: text" answers.** Five parsers (`src/domain/sections.js`, `src/itsm/sections.js`, `src/knowledge/sections.js`,
   `src/compose/notesToTicket.js`, `src/compose/emailRecommend.js`) accept different shapes (a bullet before the label, "1.", a
   full-width colon, a label without a colon, repeats). Merging them changes which AI answers are read as sections.
4. **Small:** Settings > Stored data still mentions "prices" for a storage key nothing writes any more (changing it needs a new Arabic
   text). The panel's result view keeps its own Insert logic (it inserts by a feature's spec), while the answer cards and the email
   draft now share `useInsertActions`.
5. **End-to-end flake not fully explained:** scenario `x` failed at its "fold the bar" step a few times before it was made to set
   up its own profiles; it has passed every run since, and a failure now says what the panel showed.
